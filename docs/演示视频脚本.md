# 演示视频拍摄脚本（成片 6:30–7:30）

> 要求：MP4、1080p、5–8 分钟，其中**至少 2 分钟是 AI 协同过程复现**。
> 本脚本已按「分段录制、最后拼接」设计，任何一段录坏只需重录该段。

## 一、录制前准备（5 分钟）

1. **关闭无关窗口**，只留浏览器与 AI 对话窗口，桌面背景换成纯色或简洁壁纸。
2. 浏览器窗口最大化，缩放保持 **100%**（Ctrl+0）。
3. 确认服务已启动：终端执行 `npm run dev`，看到「Key 已配置」。
4. 清空演示数据（让工作台像首次使用）：
   ```powershell
   Remove-Item -Recurse -Force server\data
   ```
   然后重启 `npm run dev`。
5. 录制工具（任选其一）：
   - **Windows 自带**：`Win + Alt + R` 开始/结束录制，文件在 `视频\捕获`。
   - **OBS Studio**：输出设置为 1920×1080、30fps、MP4。
6. 录制分辨率必须是 **1920×1080**，竖屏或缩放会导致成片不达标。

## 三、逐段旁白稿

### S1 · 片头（0:00–0:25）

> 画面：工作台首页，鼠标轻微移动，不做点击。

**旁白：**
"大家好，我是宜春学院计算机技术专业的刘子豪。这是我参加传智杯 AI 创新应用挑战赛的作品——**智卷**，一个 AI 智能出卷与批改引擎。"

### S2 · 问题（0:25–1:00）

> 画面：鼠标依次划过「已生成试卷 / 完成作答 / 平均正确率 / 覆盖知识点」四张卡片。

**旁白：**
"它解决的问题很具体：一位老师要出一份合格的单元测试卷，选题、配分、写解析、检查有没有超纲，通常要一到两个小时；而学生做完题，往往只拿到一个分数，不知道自己错在哪一步。**智卷把这两个环节都自动化了。**"

### S3 · 核心演示：双智能体流水线（1:00–2:20）★

> 操作顺序（照做即可）：
> 1. 点左侧「新建试卷」
> 2. 点快捷模板「函数极限与连续」
> 3. 把「核心知识点」改成：`函数极限、函数连续、导数与微分、微分中值定理`
> 4. 题数改 `8`，总分改 `100`
> 5. 点「生成试卷」，然后**不要再动鼠标**，让右侧轨迹自然滚动

**旁白（生成开始前）：**
"我输入四个知识点，八道题，一百分。点击生成。"
**旁白（流水线出现后，边指边说）：**
"请注意右侧——这里不是一个转圈的加载图标，而是**两个智能体在工作**。"
"第一步，出题智能体根据知识点命题。"
"第二步，本地代码做结构校验：题型对不对、选项全不全、答案在不在选项里、分值加起来是不是一百分。这一步是确定性的，不花模型一分钱。"
"第三步最关键：一个**完全独立的审题智能体**出场。它的上下文和出题者不共享，提示词要求它用敌对视角，默认假设这份卷子有问题，逐题核算答案、检查超纲和歧义。"
"如果发现问题，会打回给修复智能体，改完再查一遍，最多两轮。"

### S4 · 审题通过（2:20–3:00）

> 画面：等出现绿色「审题通过」，然后点「开始作答」。

**旁白：**
"审题通过，八道题，一百分，整条链路大约十秒。你可以看到这一栏——**整个流水线的每一步都被记录下来了**，包括审题者给出了什么评价。这是可复现性的基础。"

### S5 · 作答与批改（3:00–4:10）

> 操作：第 1 题随便选一个；第 2 题选对；第 3 题填空写答案；第 5 题简答题写两三句；然后点「提交并批改」。

**旁白：**
"现在开始作答。客观题点选项，填空题直接填，简答题可以写解题过程。"
"提交之后，客观题由确定性代码判分——单选、多选、填空完全不需要模型；只有简答题交给阅卷智能体，按评分要点给分，并要求它给出可解释的扣分理由。"

### S6 · 学情报告（4:10–5:00）

> 画面：报告页，鼠标依次划过得分环 → 雷达图 → 逐题明细 → 学情诊断。

**旁白：**
"这是学情报告。最上面是总分和正确率；中间是**知识点掌握度雷达图**，一眼能看出哪个知识点最薄弱；下面是逐题明细，每道题都有得分、错因和完整解析。"
"最下面这句是 AI 给出的学情诊断，它会直接告诉你下一步该补什么——这是学生真正需要的东西。"

### S7 · AI 协同过程复现（5:00–6:45）★ 必须 ≥2 分钟

> 画面：切到 AI 编程助手（DeepSeek Harness）的对话窗口，慢慢滚动，展示真实对话。
> 建议提前把这三段对话折叠/定位好，录制时依次展开。

**旁白（开场）：**
"最后，我想展示这个项目是怎么被做出来的——**它不是手写的，是我和 AI 协作完成的**。整个开发过程保留了完整的对话记录和提交历史。"

**① 需求与方案（约 30 秒，滚动到对话开头）**
"我最开始给 AI 的是一句很朴素的需求：一天之内做一个 AI 出题批改的完整应用。AI 没有直接开始写代码，而是先给了三个选题方向的对比和取舍，我们一起定了『出题 + 独立审题 + 自动批改』这条主线。"

**② 核心架构的取舍（约 30 秒，滚动到流水线设计处）**
"第二个关键决策是架构。AI 提出：把生成和审查拆成两次完全独立的模型调用，中间加一道确定性的结构校验，并给反馈环加轮次上限。这个决定的理由是——**验证比生成便宜**。"

**③ 真实 Bug 的定位与修复（约 55 秒，重点）**
"最有价值的是这一段。第一次跑通后，冒烟测试出现了一个很顽固的问题：审题连续三轮不通过，全链路二十三秒、一万三千 tokens，最后还是『待人工复核』。"
"我让 AI 分析原因，它给出的结论是：审题提示词只规定了『有 major 就判不通过』，却没有定义什么算 major，模型把风格建议也标成了 major。"
"修复方案分三步：写死三级严重度标准、第 2 轮起只让 blocker 阻断、修复角色只改 blocker 和 major。"
"改完之后，同一个用例第 1 轮就通过，耗时从 23.4 秒降到 10.2 秒，tokens 从 13063 降到 5426。"
"**这就是我理解的 Vibe Coding：AI 负责实现，人负责定义问题、设计约束、验收结果。**"

**④ 提交历史（可选，接着切终端）**
> 终端执行：`git log --oneline`（提前执行好，录屏时直接滚动查看）

"这是提交历史，十几次提交，每一次对应一个可以独立解释的功能落地，不是一次性把代码堆上去。"

### S8 · 技术架构与复现（6:45–7:20）

> 画面：切到 README 的架构图与复现步骤，或直接切终端执行冒烟测试。

**旁白：**
"技术上，前端 React + TypeScript，后端 Node.js + Express，模型是 DeepSeek，数据用 JSON 文件存储——**刻意不用数据库，是为了让复现足够快**。"

## 四、录制检查清单

- [ ] 分辨率 1920×1080，时长 5–8 分钟
- [ ] AI 协同过程段落 **不少于 2 分钟**（S7 建议录 1 分 50 秒以上）
- [ ] 声音清晰，无环境噪音，旁白与画面对得上
- [ ] 生成演示那次**真实调用了模型**（能看到轨迹逐步出现，而不是瞬间出现）
- [ ] 报告中能看到具体的知识点与分数
- [ ] 成片导出为 MP4（H.264），文件小于 500MB

## 五、不用重录的小技巧

- 生成过程如果失败或超时，直接点「生成试卷」重试，录屏继续，后期剪掉即可。
- 旁白可以**后期配音**：先录屏不说话，再对着脚本配音，导入剪映对齐最省时间。
- 时间不够就先保 S3、S5、S6、S7 四段，其余可缩短。
